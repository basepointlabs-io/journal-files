**Revit Doctor** watches the computer while Revit runs and explains Revit journal files in plain English. It works entirely on your computer: no AI, no uploads. From the internet it reads only two public pages: Autodesk's service status and this project's latest release on GitHub.

## What's new in 0.8.3

### Crashes during IFC export
- When Revit goes down while an IFC export is running (by hand, or a scheduled or batch export), the report now says so in its headline: "IFC export failed or crashed Revit". On one computer this explained 44 crashed sessions that were reported only as low memory before.
- The report names the elements the exporter could not export, grouped by kind (for example "901 × MW (Faceting failed)"), with lists to paste into Manage > Select by ID.
- The steps come from Autodesk's articles on IFC export errors and crashes: fix or remove the elements that fail, update Revit and the IFC Exporter, disable add-ins, export less at once with filters and "Current View Only", or with the Extra Low level of detail.
- Recognised in Revit's own English, German, French, Spanish, Italian and Portuguese wording.

### Updating
- If you have 0.8.0 or later, click **Install update** in the overview. From 0.7.3 or older, install this version once by hand.

## Requirements

- Windows 10 or 11, x64 or ARM64. Nothing else to install (.NET is included).
- Reads Autodesk's public status page (health.autodesk.com) every 5 minutes and this project's latest release on GitHub once a day; without an internet connection everything else works as before.
- Reads Revit's journals in `%LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit 20XX\Journals`, the Windows Application event log (for crash proof), the computer's resource counters, the size of model files on this computer and the graphics card's memory from the Windows registry. Nothing is sent anywhere.

## Known limitations

- The crash codes Revit records (0xe0434352, 0xe06d7363), DWG import warnings and printer-setting messages are not explained yet.
- The installer is not code-signed yet, so an update is protected by its checksum, not by a signature.
