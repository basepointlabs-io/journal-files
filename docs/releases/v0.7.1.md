**Revit Doctor** watches the computer while Revit runs and explains Revit journal files in plain English. It works entirely on your computer: no AI, no uploads. The only thing it reads from the internet is Autodesk's public service status.

## What's new in 0.7.1

### The installer works again
The installers of 0.6.1, 0.6.2 and 0.7.0 closed themselves after **Install**: they closed every program whose name starts with "RevitDoctor" so that no old copy stays running, and the installer's own name starts with it too. Nothing was installed, and no progress or finish page appeared.
- The installer now closes only copies of the app (including portable ones and Revit Journal Analyzer) and leaves itself alone.
- The app, when it replaces an older running copy, never touches an installer either.

If one of those installers got stuck for you, download this one and run it; nothing else needs to be done first.

For Autodesk service status (new in 0.7.0), see the [0.7.0 release](https://github.com/basepointlabs-io/journal-files/releases/tag/v0.7.0).

## Requirements

- Windows 10 or 11, x64 or ARM64. Nothing else to install (.NET is included).
- Reads Autodesk's public status page (health.autodesk.com) every 5 minutes; without an internet connection everything else works as before.
- Reads Revit's journals in `%LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit 20XX\Journals`, the Windows Application event log (for crash proof), the computer's resource counters and the size of model files on this computer. Nothing is sent anywhere.

## Known limitations

- The new layout is checked with automated tests and rendered screens with sample figures; please report how it behaves during real work.
- RAM needed with linked models is an estimate: Autodesk does not say how linked models add to the 20× figure.
- Sizes of linked models are known only on the computer the journal comes from, and links stay counted until that Revit is closed.
- "RAM used" is the memory Revit has taken (private bytes); Task Manager may show a little less.
