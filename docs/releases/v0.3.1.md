**Revit Journal Analyzer** explains Autodesk Revit journal files in plain English: what happened, why, and what to do. It runs entirely on your computer: no AI, no uploads.

## What's new in 0.3.1

- **A crash is only called a crash with proof.** A journal that ends without its shutdown lines now counts as a crash only when there is a crash dump next to it, a crash record in the journal, or a Windows *Application Error* event for Revit.exe. The event also names the faulting module (for example a graphics driver or `RevitDB.dll`) and the exception code in words. If Windows recorded a hang, the session is shown as "stopped responding and was closed". Everything else is "closed without shutdown record" — a forced close, or a journal copied while Revit was still running — instead of a red "crashed".
- **The "Revit crashed repeatedly" warning and the start-screen hint count proven crashes only.**
- **Each finding shows how far to trust it**: *Autodesk documentation*, *Measured in the journal*, *Confirmed by the community*, *Unconfirmed community report*, or *From the journal · cause not proven*.
- **"Not responding" alerts go to the right Revit window** when several windows of the same version are open.
- **Lighter live monitoring**: a running Revit's journal is read once, by the tray agent, from the new lines only. The window no longer re-reads the whole file, and the journal text is not kept in memory. A Revit session started while the app is open appears in the list by itself.

## Requirements

- Windows 10 or 11, x64 or ARM64. Nothing else to install (.NET is included).
- Reads the journals Revit writes to `%LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit 20XX\Journals` and, for crash proof, the Windows Application event log of the same computer. Nothing is sent anywhere.

## Known limitations

- Crash proof from the Windows event log exists only for journals of this computer and only while Windows still keeps the events (usually a few weeks).
- Journals do not contain element IDs for Revit warnings; those findings lead to *Manage → Review Warnings*.
- Live alerts for failed syncs and "not responding" are covered by automated tests; please report how they behave on your projects.
