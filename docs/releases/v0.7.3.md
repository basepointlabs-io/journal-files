**Revit Doctor** watches the computer while Revit runs and explains Revit journal files in plain English. It works entirely on your computer: no AI, no uploads. The only thing it reads from the internet is Autodesk's public service status.

## What's new in 0.7.3

### This computer and Autodesk's figures
A new list on the start screen sets this computer against what Autodesk publishes, each line with a link to the Autodesk article:
- **RAM** for the largest open model, by the system requirements table of the running Revit version: 16 GB for a model up to ~300 MB, 32 GB up to ~600 MB, 64 GB up to ~1 GB. For larger models it says that Autodesk gives no figure.
- **Free disk space:** 30 GB; Revit 2026 also recommends 100 GB for temporary files.
- **Free space for cloud models:** 20 × the model plus 3 × its linked models, on the drive with the cloud model cache. Too little space also appears under "What to do".
- **Page file:** at most twice the installed RAM.
- **Video memory:** 4 GB; 6 GB and 8 GB in the Revit 2026 Value and Performance configurations.
- **Revit Personal Accelerator:** whether it runs while cloud models are open.

### Advice with its source
- Running out of memory now reads "RAM + page file", shows how the figure is made up, and cites Autodesk: save, restart Revit, then synchronize; a page file of at most twice the RAM.
- Alerts whose level Revit Doctor sets itself (free RAM, virtual memory) say so: Autodesk publishes no figure for them.

### RAM needed counts the model only
- "RAM needed" is Autodesk's 20 × the model file. Linked models are no longer multiplied by 20 — Autodesk gives no figure for them — and are listed with their size on disk instead, with Autodesk's advice to unload the ones not in use.

### New journal findings
- **Sync stops at Reload Latest ("Element -1 has an invalid partition"):** the journal line Autodesk names for cloud models whose sync stops at Reload Latest, with the steps of that article.
- **Revit could not regenerate an element:** the report names the element, its type and what Revit was doing (for example Reload Latest > Reload Linked Instances), with Select by ID and Autodesk's steps for a serious error when reloading a link.

## Requirements

- Windows 10 or 11, x64 or ARM64. Nothing else to install (.NET is included).
- Reads Autodesk's public status page (health.autodesk.com) every 5 minutes; without an internet connection everything else works as before.
- Reads Revit's journals in `%LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit 20XX\Journals`, the Windows Application event log (for crash proof), the computer's resource counters, the size of model files on this computer and the graphics card's memory from the Windows registry. Nothing is sent anywhere.

## Known limitations

- Autodesk's RAM table is for a single model in a typical editing session; Autodesk notes that models vary.
- Sizes of linked models are known only on the computer the journal comes from; links that are not on this computer are not counted in the cloud model disk space, and the line says so.
- Internet speed for cloud worksharing (Autodesk: 5–25 Mbps symmetrical) is not measured: the app makes no network requests besides Autodesk's status page.
- "RAM used" is the memory Revit has taken (private bytes); Task Manager may show a little less.
